1) Описание
В рамках курсового проекта разрабатывается Telegram-бот, предназначенный для предоставления студентам актуального расписания занятий. Доступ к боту осуществляется через мессенджер Telegram, что не требует установки дополнительного программного обеспечения и обеспечивает удобство использования на любых устройствах.

2) Бизнес-требования
Проблема. Информация о расписании размещается на сайте вуза и в чатах групп, что затрудняет её оперативный поиск. Студенты тратят время на уточнение расписания, а сотрудники деканата — на повторяющиеся ответы и оповещения об изменениях.
Ценность для заказчика (вуза):
а) Снижение нагрузки на сотрудников деканата при информировании студентов.
б) Повышение своевременности доведения информации об изменениях в расписании.
в) Современный и удобный канал коммуникации со студентами.
Ценность для разработчиков (студентов):
г) Практический опыт разработки программного продукта.
д) Успешная защита курсового проекта и закрытие сессии.
e) Формирование навыков, применимых в дальнейшей профессиональной деятельности.
3) Функциональные требования
   Группа 1. Инициализация и управление профилем пользователя (ФТ-1)

    ФТ-1.1. Старт и первичная регистрация: При отправке команды /start система должна создавать профиль пользователя (сохранять его уникальный telegram_id и chat_id) и запускать сценарий первичной настройки.
    ФТ-1.2. Выбор академической группы: Система должна предоставлять пользователю интерактивное меню (инлайн-кнопки) с последовательным выбором: Факультет / Институт → Курс → Академическая группа.
    ФТ-1.3. Привязка группы к профилю: Выбранная группа должна сохраняться в базе данных как группа по умолчанию для данного пользователя.
    ФТ-1.4. Смена академической группы: Система должна позволять пользователю в любой момент изменить привязанную группу через раздел настроек (/settings).
    ФТ-1.5. Выбор подгруппы: Если расписание предусматривает разделение на подгруппы (например, для лабораторных работ), бот должен позволять указать конкретную подгруппу студента.

Группа 2. Предоставление расписания занятий (ФТ-2)

    ФТ-2.1. Расписание на сегодня: По команде /today или нажатию соответствующей кнопки быстрого меню бот должен выдавать список занятий на текущую календарную дату.
    ФТ-2.2. Расписание на завтра: По команде /tomorrow бот должен формировать список занятий на следующий день (с учётом переноса на понедельник, если запрос сделан в субботу/воскресенье).
    ФТ-2.3. Расписание на неделю: По команде /week бот должен отправлять расписание на текущую учебную неделю (или предоставлять выбор: «текущая неделя» / «следующая неделя»).
    ФТ-2.4. Выбор конкретной даты: Система должна позволять запросить расписание на выбранный день с помощью инлайн-календаря или ручного ввода даты.
    ФТ-2.5. Формат отображения занятия: Каждая запись о паре в сообщении должна содержать:
        Порядковый номер пары и интервал времени (время начала и окончания);
        Название дисциплины;
        Вид занятия (лекция, практика, лабораторная работа, экзамен);
        ФИО преподавателя;
        Номер аудитории и корпус (либо ссылку на конференцию при дистанционном обучении).
    ФТ-2.6. Обработка выходных и свободных дней: Если на запрашиваемую дату занятия отсутствуют (выходной, праздничный день, каникулы), система должна выводить понятное текстовое уведомление (например: «Занятий нет, можно отдыхать»).
    ФТ-2.7. Просмотр чужого расписания: Система должна предоставлять возможность разового просмотра расписания другой группы без перезаписи основной группы в профиле.

Группа 3. Загрузка, валидация и парсинг XLSX-таблиц (ФТ-3)

    ФТ-3.1. Периодическая загрузка файлов: Фоновый модуль системы должен с заданным интервалом (например, каждые 15–30 минут) отправлять сетевые запросы к внешнему серверу для проверки наличия обновлённого файла .xlsx.
    ФТ-3.2. Проверка факта изменения файла: Перед запуском ресурсоёмкого парсинга система должна проверять заголовки ответа (Last-Modified, ETag) или рассчитывать контрольную сумму (хэш) файла. Если файл не менялся, повторный парсинг выполняться не должен.
    ФТ-3.3. Разбор структуры таблицы: Модуль парсинга должен извлекать данные из листов и ячеек таблицы: сопоставлять заголовки колонок с днями недели, датами, номерами пар и наименованиями групп.
    ФТ-3.4. Атомарное обновление базы данных: Сохранение обновлённых данных в локальную БД должно происходить в рамках транзакции. В случае сбоя парсинга старые данные расписания не должны стираться.
    ФТ-3.5. Принудительная синхронизация: Система должна поддерживать команду ручного перезапуска синхронизации (доступную администраторам бота).

Группа 4. Уведомления и оповещения (ФТ-4)

    ФТ-4.1. Ежедневная рассылка: Бот должен предоставлять функцию автоматической утренней рассылки расписания на день (например, в 07:30) или вечерней рассылки на следующий день.
    ФТ-4.2. Управление подпиской: Пользователь должен иметь возможность включать/отключать автоматические уведомления и задавать удобное время их отправки.
    ФТ-4.3. Оповещения об изменениях: При фиксации изменений в расписании на ближайшие дни бот должен формировать точечные сообщения с предупреждением для студентов затронутых групп.

Группа 5. Обработка ошибок и поддержка (ФТ-5)

    ФТ-5.1. Поведение при сбое внешнего сервера: Если внешний сервер с .xlsx недоступен, бот должен продолжать отдавать расписание из локальной базы/кэша, добавляя пометку о времени последнего успешного обновления.
    ФТ-5.2. Обработка повреждённого файла: При нарушении структуры Excel-таблицы (изменение шаблона столбцов, битый файл) система должна регистрировать ошибку в логах и оповещать администратора, не прерывая работу пользовательского интерфейса.
    ФТ-5.3. Справочная система (/help): Система должна выдавать краткую инструкцию по навигации, доступным командам и контактам технической поддержки.
    ФТ-5.4. Защита от спама (Rate Limiting): Система должна ограничивать частоту запросов от одного пользователя для предотвращения перегрузки бэкенда.
5) Системные ограничения

1. Технологические ограничения

· Язык реализации — C++.
· Взаимодействие с Telegram — через Bot API, используется один бот.
· Разработка ведётся на Windows (рабочие машины команды).
· Исходный код хранится в Git, платформа — GitHub (бесплатный тариф).

2. Ограничения по хостингу

· Бот должен работать круглосуточно (24/7).
· Бюджет проекта — 0 рублей.

3. Ограничения по данным

· Хранятся только Telegram ID пользователя и номер группы; персональные данные (ФИО, контакты) не сохраняются.
· Бот не формирует расписание самостоятельно, а только отображает загруженное.

4. Ограничения по срокам

· Проект должен быть завершён к концу первого семестра.

5. Ограничения по нагрузке и доступности

· Целевая аудитория — студенты факультета ИРИТ (один факультет).
· Время отклика бота — не более 2 секунд.
· Требуемая доступность — 24/7.

6. Ограничения по интерфейсу

· Взаимодействие пользователя с системой — только через Telegram.
· Отдельное приложение, сайт или веб-панель не предусмотрены.
· Управление — через команды и кнопки бота.
