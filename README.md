1. Описание

В рамках курсового проекта разрабатывается Telegram-бот для предоставления студентам факультета ИРИТ актуального расписания занятий. Работа через Telegram не требует установки дополнительного ПО и позволяет пользоваться сервисом с разных устройств. Бот не формирует расписание самостоятельно, а отображает данные из загруженных источников.

2. Бизнес-требования
Проблема: Расписание публикуется на сайте вуза и в групповых чатах, из-за чего его неудобно быстро находить. Студенты тратят время на уточнение расписания, а сотрудники деканата — на однотипные ответы и ручное оповещение об изменениях.
Ценность для заказчика (вуза / факультета ИРИТ):
    снижение нагрузки на сотрудников деканата при информировании студентов;
    более оперативное доведение информации об изменениях в расписании;
    удобный и современный канал коммуникации со студентами.
Ценность для команды разработчиков:
    практический опыт создания и сопровождения программного продукта;
    успешная защита курсового проекта и закрытие сессии;
    развитие навыков, полезных в дальнейшей профессиональной работе.

3. Пользовательские требования

Пользователь должен иметь возможность:
    при первом запуске указать свою учебную группу ИРИТ (и при необходимости подгруппу);
    в любой момент изменить выбранную группу;
    получать актуальное расписание на сегодня, завтра или выбранную дату;
    получать расписание на текущую, следующую или выбранную неделю;
    видеть полную информацию о каждом занятии, нужную для посещения;
    получать понятное сообщение, если на выбранную дату занятий нет;
    получать понятное сообщение, если расписание на нужную дату ещё не опубликовано или временно недоступно;
    получать расписание автоматически по расписанию или при изменениях без ручного запроса.

4. Функциональные требования

Группа 1. Инициализация и управление профилем пользователя (ФТ-1)
    ФТ-1.1. Старт и первичная регистрация: по команде /start система создаёт профиль пользователя (сохраняя telegram_id и chat_id) и запускает первичную настройку.
    ФТ-1.2. Выбор академической группы: система предлагает интерактивное меню с инлайн-кнопками для последовательного выбора внутри факультета ИРИТ: Курс → Академическая группа.
    ФТ-1.3. Привязка группы к профилю: выбранная группа сохраняется в базе данных как основная для пользователя.
    ФТ-1.4. Смена академической группы: пользователь может изменить привязанную группу через настройки (/settings).
    ФТ-1.5. Выбор подгруппы: при наличии деления на подгруппы (например, на лабораторных работах) бот позволяет указать свою подгруппу.

Группа 2. Предоставление расписания занятий (ФТ-2)
    ФТ-2.1. Расписание на сегодня: по кнопке с командой /today (или при вызове команды) бот выводит занятия на текущую дату.
    ФТ-2.2. Расписание на завтра: по кнопке с командой /tomorrow (или при вызове команды) бот выводит занятия на следующий календарный день без переноса на понедельник; если на этот день занятий нет — выводит сообщение об отсутствии занятий.
    ФТ-2.3. Расписание на неделю: по кнопке с командой /week (или при вызове команды) бот отправляет расписание на учебную неделю с выбором между текущей и следующей неделей.
    ФТ-2.4. Выбор конкретной даты: пользователь может выбрать дату через инлайн-календарь или ввести её вручную.
    ФТ-2.5. Формат отображения занятия: каждая запись о паре включает:
        порядковый номер и интервал времени (начало и окончание);
        название дисциплины;
        вид занятия (лекция, практика, лабораторная работа, экзамен);
        ФИО преподавателя;
        аудиторию и корпус (либо ссылку на онлайн-занятие при дистанционном формате).
    ФТ-2.6. Обработка выходных и свободных дней: если занятий на выбранную дату нет (выходной, праздник, каникулы), выводится понятное сообщение (например: «Занятий нет, можно отдыхать»).
    ФТ-2.7. Просмотр расписания другой группы: бот позволяет разово посмотреть расписание другой группы ИРИТ, не меняя основную группу в профиле пользователя.

Группа 3. Загрузка, валидация, конвертация и парсинг таблиц (ФТ-3)
    ФТ-3.1. Периодическая загрузка файлов: фоновый модуль с заданным интервалом (например, каждые 15–30 минут) проверяет внешний источник на наличие обновлённого .xlsx-файла.
    ФТ-3.2. Проверка факта изменения файла: перед конвертацией и парсингом проверяются заголовки (Last-Modified, ETag) или хэш файла; если изменений нет, повторная обработка не запускается.
    ФТ-3.3. Конвертация Excel в JSON и разбор структуры: система конвертирует данные из .xlsx в JSON и извлекает расписание из листов и ячеек, сопоставляя заголовки с днями недели, датами, номерами пар и группами ИРИТ.
    ФТ-3.4. Атомарное обновление базы данных: запись новых данных в локальную БД выполняется в рамках транзакции, чтобы при ошибке конвертации/парсинга не потерять актуальные старые данные.
    ФТ-3.5. Принудительная синхронизация: администраторам бота доступна команда ручного запуска синхронизации.

Группа 4. Уведомления и оповещения (ФТ-4)
    ФТ-4.1. Ежедневная рассылка: поддержка автоматической утренней (например, в 07:30) или вечерней рассылки расписания.
    ФТ-4.2. Управление подпиской: пользователь может включать и отключать автоуведомления и выбирать удобное время отправки.
    ФТ-4.3. Оповещения об изменениях: при обнаружении изменений в расписании на ближайшие дни бот отправляет уведомления студентам затронутых групп.

Группа 5. Обработка ошибок и поддержка (ФТ-5)
    ФТ-5.1. Сбой внешнего источника: если источник с .xlsx недоступен, бот продолжает отдавать расписание из локальной БД/кэша с указанием времени последнего успешного обновления.
    ФТ-5.2. Повреждённый файл или нарушение шаблона: при ошибке конвертации/парсинга, нарушении структуры таблицы или битом файле система пишет ошибку в лог и уведомляет администратора, не останавливая работу бота для пользователей.
    ФТ-5.3. Справочная система (/help): выводит краткую справку по навигации, командам и контактам поддержки.
    ФТ-5.4. Защита от спама (Rate Limiting): ограничивает частоту запросов от одного пользователя (до 10 запросов в минуту) для защиты от перегрузки.
    
5. Ограничения и нефункциональные требования
   
5.1. Стек и технологические ограничения
    Взаимодействие с платформой: работа осуществляется исключительно через Telegram Bot API в рамках одного бота; отдельные мобильные приложения, сайты или веб-панели проектом не предусмотрены.
    Языки разработки: в реализации используются два языка — C++ и Python.
    Среда разработки и хранение кода: разработка ведётся на рабочих станциях команды под управлением Windows; управление версиями и хранение исходного кода выполняются в Git на платформе GitHub (бесплатный тариф).
    Хранилище и формат данных: для хранения данных применяется реляционная СУБД (SQLite или PostgreSQL); входным форматом данных является Excel (.xlsx) с последующим преобразованием в JSON.
    Сопровождение и документация: код должен иметь модульную архитектуру, сопровождаться документацией, логированием критических событий и по возможности настроенным CI/CD для автоматического развёртывания.

5.2. Производительность и нагрузка
    Время отклика: система должна отвечать на запросы и команды пользователя не дольше 1,5 секунд при штатной работе.
    Целевая аудитория и нагрузка: целевая аудитория сервиса — студенты факультета ИРИТ.
    Ограничение частоты запросов (Rate Limiting): для защиты от спама и перегрузки бэкенда частота запросов от одного пользователя ограничивается значением не более 10 запросов в минуту.

5.3. Надёжность и доступность
    Режим работы и бюджет: сервис должен обеспечивать круглосуточную работу в режиме 24/7 при бюджете проекта 0 рублей.
    Доступность и отказоустойчивость: целевой уровень доступности — не ниже 99,5%; при сбое узла предполагается автоматическое переключение на резервный узел в течение 30 секунд в рамках бюджета 0 рублей7.
    Резервное копирование и целостность данных: выполняется ежедневное резервное копирование базы данных; бот не формирует расписание самостоятельно, а только отображает загруженные данные, сохраняя при сбоях актуальное состояние из локальной БД/кэша.
    Сроки реализации: проект должен быть завершён и готов к защите к концу первого семестра.

5.4. Безопасность и работа с данными
    Состав хранимых данных: система сохраняет только технические и учебные атрибуты профиля (telegram_id, chat_id, выбранную академическую группу/подгруппу факультета ИРИТ и пользовательские настройки уведомлений); персональные данные вроде ФИО и контактов не собираются и не хранятся.
    Защита при передаче и хранении: передача данных между компонентами и внешними сервисами осуществляется по защищённому протоколу HTTPS (TLS 1.2+), а доступ к базе данных, логам и административным настройкам ограничивается для предотвращения несанкционированного доступа.

5.5. Интерфейс и пользовательский опыт
    Навигация и элементы управления: взаимодействие с пользователем строится на кнопках (на которых выведены команды) с поддержкой ввода команд и ручного ввода даты там, где это предусмотрено сценарием.
    Кроссплатформенность: интерфейс должен корректно отображаться и работать на всех поддерживаемых клиентах Telegram (iOS, Android, Web, Desktop).
    Предсказуемость сценариев: при отсутствии занятий на запрашиваемую дату (в том числе по команде /tomorrow без переноса на понедельник) бот выводит понятное текстовое уведомление без перехода на другой день.
